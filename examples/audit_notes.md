- Live command path: `repo-triage python/cpython --limit 10 --export`.
  A temporary observer invoked the real CLI entry function and wrapped the real
  LiteLLM completion and report builder to count calls and capture their inputs
  and validated results. No GitHub or model responses were mocked in this run.
- Generated: **2026-10-28 16:08:29 UTC**; exit code **0**; runtime **9.224 s**;
  **10 actual open issues**, **1 LiteLLM completion invocation**.
- [Sample report](sample_report.md) is the exported report, checked for configured
  credential values and common OpenAI/GitHub token formats. No redaction was
  needed. It includes public issue titles, URLs, and model suggestions only.
- CPython was selected because the earlier Flask sample contained only one issue.
  The application still samples recent activity, not the complete backlog.
- The baseline below is **most recently updated first**, the GitHub client's
  existing `sort=updated&direction=desc`, not creation-date order. Both orders
  use the exact same captured sample; no later refresh or second LLM call was used.
- All ten source titles, bodies supplied to the model, labels, and results were
  inspected. Bodies were limited to 800 characters; linked pages, attachments,
  later comments, and reproduction results were not inspected.

## Tests, safety checks, and fixes

- **83 pytest tests passed; 1 optional live-model test skipped.** The separate
  real CLI run above succeeded. Existing tests were retained; focused additions
  cover valid repository inputs, ranking independent of input order, the actual
  provider's two-attempt ceiling, injected issue text, and secret-bearing errors.
- Coverage includes invalid repository identifiers, PR filtering, 800-character
  truncation, limits, two-page bounds, strict Pydantic fields, missing/duplicate/
  invented issue numbers, rate limits, model failures, export failures, and
  deterministic ranking.
- Mocked injection data requests command execution, secret disclosure, and issue
  999. Assertions check no shell/subprocess calls, no marker file, no tools sent
  to the model, and no credential in messages or output. The mocked completion
  is controlled by the test: **this does not prove a real LLM cannot be manipulated**.
- Fixed raw provider-lookup errors escaping the CLI's safe exception wrapper.
  Regression tests inject a credential-bearing error into both provider lookup
  and completion and verify no raw message/traceback appears.
- Added `max_retries=0` alongside `num_retries=0`, explicitly disabling SDK as
  well as LiteLLM transport retry settings. Application-level completions are
  bounded at two (only malformed output gets one repair attempt); empty samples
  make zero calls. The live count was one. Counts refer to LiteLLM invocations,
  not an independently traced count of every provider-internal HTTP operation.
- `.env` is ignored and not tracked; `.env.example` contains placeholders only.
  A scan of nonignored workspace files and both local Git commits found no
  configured credential values or common OpenAI/GitHub token patterns. The
  ignored `.env` intentionally holds local credentials. This scan is not a
  comprehensive detector for all possible secret formats.

No features were added. Remaining limitations are semantic model errors, body
truncation, activity-based sampling, and the lack of independent severity ground
truth. No prompt changes were made to hide weaknesses found in this single run.
